# SD Apps

Optional application bundle for ESP32-S3 boards using an SD card as `/home`.

The default firmware images are not changed. N16R8 remains self-contained.

## Build

Run from the repository root:

    ./sd-apps/build.sh

The generated archive is written to:

    sd-apps/output/sd-apps-<version>.tar.gz

For example:

    sd-apps/output/sd-apps-0.8.1.tar.gz

## Build source

The SD Apps builder uses the same N16R8 Buildroot userspace, toolchain, and libc as the firmware.

The build order is:

1. Reuse an existing N16R8 Buildroot userspace if available.
2. Otherwise build the N16R8 userspace using the existing build caches.
3. If no cache is available, build the required N16R8 userspace from scratch.

The normal firmware build path (`run.sh`) is not modified or required.

## Included applications

The initial bundle contains:

- curl
- Dropbear SSH server
- ssh
- scp
- dbclient
- dropbearkey
- dropbearconvert
- libcurl
- mbedTLS libraries required by curl

Libraries already provided by the firmware, such as `libc.so.0` and
`libatomic.so.1`, are not duplicated in the SD Apps bundle.

## Archive layout

The archive is installed under `/home`:

    /home/bin/
    /home/sbin/
    /home/lib/

Application and library symlinks generated by Buildroot are preserved.

## Runtime note

ESP32-S3 has no MMU, so applications stored on the SD card cannot use XIP.
An executable is loaded into RAM when it runs.

Memory usage should therefore be checked when running larger applications,
especially curl with TLS.
